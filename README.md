A single, self-contained Progressive Web App: no server, no account, no tracking, no CDN.

> **Vision:** help any individual practitioner assemble a personal materia medica and repertory — every remedy, symptom, rubric and grade defined and edited by hand — then publish or back it up in whatever shape they need.

## 🚀 Try it

**Live app:** **https://drsamonline.github.io/MATERIA-MEDICA-BUILDER/**

Open it in any modern browser, or install it (Chrome/Edge → install icon; iOS Safari → Share → *Add to Home Screen*) and it runs fully offline.

---

## ✨ What it does

| Area | What you get |
|---|---|
| **Materia Medica** | Remedies with name, abbreviation, common name, kingdom, family, source and notes. Add any number of symptoms to each, each with a chapter, grade and modalities. |
| **Repertory** | Chapters (Mind, Head, Stomach…) → rubrics → graded remedies. Rubrics support a parent heading and a note. |
| **Marking system** | Define the grading scale yourself. Four presets ship in (Kent 3-point, 4-point with capitals, Boenninghausen 5-point, Simple 0–2) and you can edit any of them or add your own schemes with custom levels, labels and styles (plain / italic / bold / bold-italic / caps / superscript). |
| **Author & branding** | Your name, credentials, clinic, email, website, book title, edition, year, copyright line and licence — stamped into every PDF, HTML file and workbook you export. |
| **Cases** | The original case logger is kept as its own tab: log a case, track the outcome (Cured / Improved / No Change / Aggravated / Suppressed) and review the history. |
| **Dashboard** | Live counts for remedies, symptoms, chapters, rubrics and cases, plus a success rate and recent cases. |

Everything is stored **locally in your browser** (IndexedDB). Nothing is uploaded anywhere.

## 📤 Export & import

**Export** (Data tab):

| Format | Contents |
|---|---|
| **JSON — full backup** | Everything, re-importable here to restore the whole project. |
| **JSON — OMM repertory** | Reader-app schema v1.1: `sections → rubrics → remedy_table`. |
| **JSON — OMM materia medica** | Reader-app schema v1.1: `remedies → symptoms`. |
| **JSON — OMM both** | A zip containing both of the above. |
| **CSV — all datasets** | A zip of `remedies.csv`, `symptoms.csv`, `repertory.csv`, `cases.csv`. |
| **CSV — single dataset** | Any one of the four as a single file. |
| **Excel (.xlsx)** | A real workbook: Info, Remedies, Symptoms, Repertory, Cases, Marking. |
| **PDF** | A printable document with your author block and copyright. |
| **HTML** | A self-contained, styled, viewable document. |
| **SQL (.sql)** | Portable `INSERT` statements — load into SQLite, Postgres or MySQL. |
| **SQLite (.sqlite)** | A real SQLite 3 database file (`meta`, `remedy`, `symptom`, `rubric`, `remedy_link`, `case_log`). |

**Import** (Data tab): JSON is auto-detected — a full backup *or* an OMM repertory / materia-medica file. CSV is imported per dataset (remedies, symptoms, repertory, cases). Choose **Merge** (add to what's there) or **Replace** (wipe and load).

All writers are **dependency-free** and run entirely in the browser — the `.xlsx`, `.pdf` and `.sqlite` files are generated byte-by-byte in JavaScript, so the app never needs a network connection or a library from a CDN.

## 🔗 Compatibility with the OMM reader app

The JSON exports use the same envelope your reader app already reads (`schema_version: "1.1"`, `type: "repertory"` / `"materia_medica"`, a `book` provenance block, and `sections → rubrics → remedy_table` / `remedies → symptoms`). A repertory you build here can be dropped straight into that collection, and a book extracted by the OMM pipeline can be imported here for editing.

## 🛠️ Running it locally

```bash
python3 -m http.server 8080     # then open http://localhost:8080
```

Deploy anywhere static — GitHub Pages, Netlify, Cloudflare Pages. The service worker takes it offline automatically.

## 🧱 Data model

```
remedy   { id, name, abbrev, common_name, kingdom, family, source, notes }
symptom  { id, remedy_id, chapter, text, grade, modalities[{dir,text}], notes }
section  { id, title, order }
rubric   { id, section_id, text, parent, note, remedies[{remedy_id, grade, polarity, note}] }
case     { id, patient_initials, age, gender, chief_complaint, prescribed_remedy_id,
           potency, dosage, outcome, follow_up_notes, date }
settings { author{…}, marking{active, schemes[{id,name,levels[{v,label,style}]}]} }
```

`grade` is a level value from the active marking scheme. `polarity` is `+` (default) or `-` (antidotal).

**Upgrading from v1:** the app opens the same `MateriaMedicaDB` database at version 2 and adds the new stores — existing remedies, symptoms and cases are preserved and old symptom fields are migrated automatically.
