# MATERIA MEDICA BUILDER — user guide

**Version 1.0.0 · PolyForm Noncommercial 1.0.0**

Build your own materia medica and repertory, then export it as a book. Everything is stored
in your browser (IndexedDB); nothing is uploaded anywhere.

- Open the app: <https://drsamonline.github.io/MATERIA-MEDICA-BUILDER/>
- Run it locally: `python3 -m http.server 8080`, then open <http://localhost:8080>

The app carries this same guide in its **Help** tab, plus a first-run tour. This page is the
version you can read before opening it.

## First hour

1. **Materia Medica** tab → add a remedy (or edit the three starters). Give it an
   abbreviation — `Acon`, `Nat-m` — because that is what the repertory displays.
2. Add symptoms to that remedy: chapter (Mind, Head, Stomach…), the symptom, a grade.
3. **Repertory** tab → add a chapter, then rubrics inside it.
4. Inside a rubric, type a remedy abbreviation and press **Enter** to attach it, then pick
   the grade.
5. Fill in **Author** details — they are stamped into every export.
6. **Data** tab → export.

## The marking scale is yours

Four schemes ship in: **Kent 3-point**, **4-point with capitals**, **Boenninghausen
5-point** and **Simple 0–2**. *New scheme* defines your own: any number of levels, each with
a label and a style (plain, italic, bold, bold-italic, capitals, superscript). Every rubric
and every export renders the active scheme — so a book exported with your scale reads in
your scale, not in a fixed one.

## What you can export

| Format | What it is for |
|---|---|
| JSON — full backup | everything, re-importable to restore the project |
| JSON — OMM | repertory and/or materia medica in the reader-app schema (v1.1) |
| CSV | all datasets as a zip, or one at a time |
| Excel `.xlsx` | a workbook: Info, Remedies, Symptoms, Repertory, Cases, Marking |
| PDF | a printable book with your author block and copyright |
| HTML | a self-contained styled document you can open or host |
| SQL `.sql` | portable `INSERT` statements for SQLite, Postgres or MySQL |
| SQLite `.sqlite` | a real database file: `meta`, `remedy`, `symptom`, `rubric`, `remedy_link`, `case_log` |

Import accepts a full JSON backup, an OMM repertory or materia-medica file, or CSV, in
**Merge** or **Replace** mode.

## Your data, and the one thing to do about it

Your work lives **only in this browser**. There is no account and no sync, which is the
point — but it also means a cleared browser profile is a lost book. Export a JSON backup
regularly and import it on another device to carry the project across.

## Compatibility with the reader app

The JSON exports use the envelope the OMM reader reads (`schema_version: "1.1"`,
`type: "repertory"` or `"materia_medica"`, a `book` provenance block, and
`sections → rubrics → remedy_table`). A repertory built here drops straight into that
collection, and a book extracted by the OMM pipeline can be imported here for editing.

## Under the hood, briefly

Every writer is dependency-free and runs in the browser: the `.xlsx`, `.pdf` and `.sqlite`
files are generated byte by byte in JavaScript, so the app never needs a CDN, a network
connection or a server. Deploy it on any static host; the service worker makes it work
offline after the first load.
